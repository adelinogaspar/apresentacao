01 · o terreno

Bash: três casas,
a mesma linguagem

Git Bash, Linux e macOS têm detalhes diferentes, mas todos executam os mesmos scripts. A peça que amarra tudo isso é o ~/.bashrc.

linux

bash 4 / 5

Bash moderno e interativo: cada terminal novo lê ~/.bashrc. É o cenário mais previsível — use ele como referência.

macOS

bash 3.2 + zsh

O bash do sistema é antigo (3.2) e o shell padrão é zsh. Se você abrir bash no Terminal, ele é um shell de login: lê ~/.bash_profile. Cole a linha do bootstrap nos dois arquivos.

Windows

Git Bash

MSYS2 dentro do Git for Windows: tem ~, ~/.bashrc, aliases e functions como no Linux. A mesma sequência de comandos funciona sem mudança.

Regra de ouro: um script só é aproveitado se ele for source-ado no shell atual. source bootstrap.sh roda no shell que está aberto; bash bootstrap.sh cria um filho e nada sobra (aliases e functions somem).

02 · o arquivo mágico

~/.bashrc — o cérebro
de cada terminal novo

Toda vez que você abre um bash interativo, ele executa este arquivo linha a linha. Tudo que você quer que "exista sempre" vive aqui.

# ~/.bashrc — executado a cada shell interativo source $HOME/dev/bash/bootstrap.sh # carrega funções e aliases alias g="git" alias ll="ls -lh" # functions: java-set, mvn-build, ...
quando roda

Terminal novo, tmux, Git Bash, VS Code. Não roda em bash script.sh nem em shells não interativos (CI, cron).

por que é bom

Um único ponto de configuração para PATH, JAVA_HOME, aliases, functions, prompt. Instalar uma ferramenta = escrever uma linha.

como adicionar sem duplicar

grep -qxF 'source ...' ~/.bashrc || echo 'source ...' >> ~/.bashrc — só adiciona se ainda não existe. Rode 10 vezes, nada quebra.

03 · o toolkit

Três arquivos,
zero magia

Um zip pequeno que você joga em ~/dev/bash. O bootstrap.sh é o único ponto de entrada: ele só source-a os outros.

~/dev/bash/ bootstrap.sh ← porta de entrada java.sh ← java-set, java-set-from-pom maven.sh ← mvn-build, mvn-build-skip-tests ~/opt/ java/ jdk-25 jdk-21 jdk-17 jdk-11 maven/ apache-maven-3.10.0
#!/usr/bin/env bash # bootstrap.sh — só carrega os outros scripts BASH_HOME="${BASH_SOURCE[0]%/*}" source "$BASH_HOME/java.sh" source "$BASH_HOME/maven.sh"
KISS: nenhum if, nenhum export misterioso. BASH_HOME vem do próprio arquivo, então o toolkit funciona em ~/dev/bash ou em qualquer outro lugar.

04 · java.sh

Uma versão de Java
por projeto

Cada JDK fica em ~/opt/java/jdk-<versão>. Um comando troca o JAVA_HOME, o PATH e os aliases na hora.

java-set() { java_home="$HOME/opt/java/jdk-$1" if [ ! -d "$java_home" ]; then echo "Java $1 não existe em $java_home" >&2 return 1 fi export JAVA_HOME="$java_home" export PATH="$JAVA_HOME/bin:$PATH" alias java="$JAVA_HOME/bin/java" alias keytool="$JAVA_HOME/bin/keytool" echo "Java $1 ativado ✔" } java-set-from-pom() { version=$(grep -oE '<(java.version|maven.compiler.release)>[0-9]+' pom.xml \ | head -n 1 | grep -oE '[0-9]+') java-set "$version" }
$ cd ~/dev/legacy-app $ java-set-from-pom Java 11 ativado ✔ $ java -version openjdk 11.0.2 $ cd ~/dev/new-app $ java-set 25 Java 25 ativado ✔
por que funciona

O alias aponta direto para o binário certo, então nem depende do PATH estar 100% sincronizado — e o keytool acompanha a mesma versão.

dica

Chame java-set-from-pom num .bashrc por projeto, ou simplesmente antes do build. O mvn-build já faz isso por você.

05 · maven.sh

Build certo,
sem decorar comando

mvn-build garante o Java do pom, usa settings.xml se existir e aceita parâmetros extras.

mvn-build() { java-set-from-pom # garante o Java certo antes de buildar if [ -f settings.xml ]; then mvn clean package -s settings.xml "$@" else mvn clean package "$@" fi } mvn-build-skip-tests() { mvn-build -DskipTests "$@" }
$ mvn-build Java 17 ativado ✔ BUILD SUCCESS · target/app.jar $ mvn-build-skip-tests -Dmaven.main.skip $ mvn-build -Dcheckstyle.skip
base para outros comandos

"$@" deixa você anexar qualquer flag do Maven. mvn-build-skip-tests é só mvn-build com -DskipTests — zero duplicação.

06 · setup

Instalação em 4 passos
iguais em Windows, macOS e Linux

1mkdir -p ~/opt/{java,maven} — onde os JDKs e o Maven vão morar
2mkdir -p ~/dev/bash — a casa dos scripts
3unzip bash-toolkit.zip -d ~/dev/bash — bootstrap.sh, java.sh, maven.sh
4grep -qxF 'source $HOME/dev/bash/bootstrap.sh' ~/.bashrc 2>/dev/null || echo 'source $HOME/dev/bash/bootstrap.sh' >> ~/.bashrc — idempotente, pode rodar quantas vezes quiser
Dois cuidados: 1) o bootstrap precisa do caminho real ($HOME/dev/bash/bootstrap.sh), não de $HOME/bootstrap.sh. 2) no macOS, se o Terminal abre bash como shell de login, repita a linha em ~/.bash_profile também.
Windows — Git Bash: ~ é %USERPROFILE%, os comandos são idênticos.
macOS — mesma estrutura; use bash explícito ou adapte para zsh.
Linux — funciona como está. Recarregue com source ~/.bashrc.

08 · java 25

Threads virtuais:
milhares de "fantasmas"
num só corpo

Thread virtual = objeto barato managed pela JVM. Ela monta e desmonta sobre threads reais, então você cria dezenas de milhares sem esgotar memória nem o CPU.

// 1. a forma mais simples var t = Thread.startVirtualThread(() -> System.out.println("boo!")); t.join(); // 2. uma thread virtual POR tarefa (o padrão em requests) try (var executor = Executors.newVirtualThreadPerTaskExecutor()) { IntStream.range(0, 100_000).forEach(i -> executor.submit(() -> fetchGhost(i)) // bloquear aqui é barato ); } // 3. Java 25 (preview): Structured Concurrency + Scoped Values try (var scope = StructuredContext.newScope(50, 1_000)) { scope.spawn(() -> checkHaunt(1L)); scope.join(); }
o que mudou no 25

LTS desde 16/09/2025. Threads virtuais são final desde o Java 21 (JEP 444); no 25 chegam Scoped Values finalizadas (JEP 506) e Structured Concurrency em preview (JEP 505), além do fim do pinning (JEP 491).

quando usar

I/O-bound: HTTP, banco, filas. CPU-bound ainda precisa de paralelismo real — thread virtual não multiplica núcleos.

cuidados

synchronized e System.out costumam "pinar" a thread. Migrar synchronized → ReentrantLock resolve.

Plataforma vs virtual

java-set 25troca o JDK do shell atual
java-set-from-pomlê a versão do pom.xml
mvn-buildsettings.xml + args extras
mvn-build-skip-testsbuild rápido, sem testes
1 MB vs ~100 bytes — o custo de uma thread é o gargalo, não o CPU.
1:1 vs N:1 — virtual troca stack nativa por continuations no heap.
Monta/desmonta — quando bloqueia, o carrier continua trabalhando.
